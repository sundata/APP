# Devin AI 开发任务书：日本女性向每日占卜 App「Koyomi（こよみ）」

> 请 Devin 将本文视为产品需求文档、技术方案和验收清单。目标不是只做静态 Demo，而是交付一个可在真机运行、可测试、可继续上架迭代的 iOS MVP。

## 1. 产品一句话

制作一款面向日本 18～35 岁女性的日语 iOS App：每天结合用户星座、当地天气、日期与天文节律，生成漂亮、有趣、温柔且有行动价值的「今日のおまもり占い」。

暂定产品名：**Koyomi（こよみ）**  
日语副标题：**空と星から届く、わたしだけの毎日占い**

产品体验关键词：

- 上品、治愈、有灵气，但不要廉价或过度梦幻；
- 像一位懂生活的日本女性朋友，而不是神秘主义大师；
- 每条结果都能转化成一个今天可以完成的小行动；
- 打开后 10 秒内看到最重要的结果；
- 分享图足够漂亮，让用户愿意发到 Instagram Stories 或 LINE。

## 2. MVP 成功标准

首版必须实现：

1. 用户用日语完成出生日期、星座和位置权限的 onboarding；
2. App 获取当前位置对应的实时天气；拒绝定位时可手动选择日本城市；
3. 根据日期计算太阳星座，并生成可复现的每日占卜结果；
4. 首页展示综合运、恋爱、工作/学习、美容健康、幸运色、幸运物和今日行动；
5. 显示天气与占卜之间自然、有趣的联系；
6. 提供收藏、历史记录和日语分享卡；
7. 支持每日提醒，且只有用户主动开启后才请求通知权限；
8. 无网络、无定位、API 超时或生成服务失败时仍有完整可用的 fallback 结果；
9. 完成单元测试、基础 UI 测试、README、配置说明和隐私说明；
10. 所有用户可见文案必须是自然的日语，不出现中文或开发占位符。

建议观测但不阻塞首版上线的指标：onboarding 完成率、通知开启率、次日/7 日留存、分享率、收藏率、每日占卜展开率。埋点不得保存精确位置或完整生日。

## 3. 用户与品牌方向

### 3.1 核心用户

- 居住在日本、每天看天气和轻占卜的 18～35 岁女性；
- 喜欢美容、穿搭、咖啡店、手账、季节感和仪式感；
- 希望得到情绪支持与具体建议，但不喜欢恐吓、宿命论或说教。

### 3.2 视觉语言

- 主色：夜空蓝 `#252544`、雾紫 `#8D83B8`、月光米白 `#FAF7F2`；
- 点缀色根据每日幸运色变化，但文字对比度始终符合 WCAG AA；
- 卡片使用柔和渐变、微颗粒、星点和玻璃感，避免大面积高饱和粉色；
- 字体优先使用系统日文字体，正文保证 Dynamic Type 和可读性；
- 动效：星点缓慢呼吸、卡片轻微浮动，必须尊重“减少动态效果”；
- 深色模式使用深靛蓝而非纯黑；
- 不要使用未经授权的动漫角色、品牌图案或素材。

## 4. 信息架构与页面

底部 3 个 Tab：

1. **今日**：当天占卜主页面；
2. **カレンダー**：历史结果、收藏和连续打卡；
3. **わたし**：个人资料、城市、提醒、隐私和免责声明。

### 4.1 Onboarding

建议 4 屏，不强制注册：

1. 品牌介绍：`今日の空は、今日のあなたの味方。`
2. 昵称与出生日期；根据生日自动显示星座，允许用户确认；
3. 解释定位用途后再请求系统权限：`今いる場所のお天気を、占いにそっと重ねます。`
4. 选择提醒时间（默认 07:30），用户点击开启后再请求通知权限；提供“あとで”跳过。

禁止索取出生时间、精确出生地点、手机号或账号，除非后续功能确有必要。生日只需保存在设备本地。

### 4.2 今日页

从上到下：

- 日期、城市、天气图标、温度与一句季节问候；
- 主卡：`今日の運勢`、五颗星评分、80～120 字日语总评；
- `空からのサイン`：说明天气/季节/天象如何对应今天的情绪或行动；
- 四项小卡：`恋愛運`、`仕事・勉強運`、`美容・健康運`、`対人運`；
- 幸运区：`ラッキーカラー`、`ラッキーアイテム`、`ラッキータイム`；
- `今日の小さなアクション`：必须是低成本、可执行、无压力的一个动作；
- 收藏按钮与 `シェアカードをつくる`；
- 轻量说明：`占いは毎日を楽しむためのヒントです。`

交互要求：首次加载使用骨架屏；下拉可刷新天气，但同一用户同一天的核心占卜不能因为刷新而反复改变。

### 4.3 日历页

- 月历标记已查看、已收藏日期；
- 点击过去日期查看当时保存的天气摘要和占卜；
- 展示连续使用天数，但断签时不用红色警告或负面文案；
- MVP 历史数据只保存在本机。

### 4.4 分享卡

- 生成适合 Stories 的 9:16 图片，并提供简洁 1:1 版本；
- 默认只包含日期、星座、综合短句、幸运色和品牌名；
- 不显示昵称、位置、生日等个人信息；
- 使用 iOS 原生分享面板，可保存图片；
- 即使离线也能生成。

## 5. 占卜内容规则

### 5.1 输入

- 用户：太阳星座、可选昵称；
- 时间：用户当地日期、星期、月份、季节、月相；
- 天气：天气类型、当前温度、最高/最低温、降水概率、湿度、风；
- 可选天象：只使用可靠数据源返回的月相或主要天文事件；无法可靠获取时不要编造。

不要把星座与天气伪装成科学因果。`空からのサイン` 是富有诗意的生活提示，不是事实判断。

### 5.2 稳定且可测试的生成策略

核心结果采用“规则引擎 + 模板内容”，不要让线上 LLM 成为首屏的单点依赖：

1. 使用 `localDate + zodiac + weatherCategory + contentVersion` 生成稳定 seed；
2. seed 从已审核的日语内容池中选择主题、建议、幸运元素和措辞；
3. 天气映射为有限枚举：晴、阴、雨、雪、雷雨、雾、强风、极端温度；
4. 相同本地日期、星座、城市天气快照应返回相同结果；
5. 将最终结果和天气快照持久化，确保历史页面不会变化；
6. 内容池至少准备每个星座 20 条主题、每种天气 10 条提示，并通过组合降低重复率；
7. 连续 7 天不能出现完全相同的总评或今日行动。

如接入 LLM，只允许服务端用于改写已批准素材；必须有 JSON Schema 校验、超时、缓存、速率限制、内容安全过滤和模板 fallback。不得把任何 API key 放在 iOS 客户端。

### 5.4 日语编辑标准

- 语气用温柔、自然的です／ます体；短句为主；
- 用 `〜してみて`、`〜かもしれません`，少用命令式；
- 不用 `絶対`、`必ず当たる`、`運命` 等确定性承诺；
- 坏天气不等于坏运势，低分也必须给出建设性出口；
- 不制造焦虑，不以恋爱或婚姻定义女性价值；
- 不预测死亡、疾病、怀孕、背叛、事故、投资收益或考试结果；
- 不提供医疗、法律、金融诊断或建议；
- 健康文案只能是喝水、休息、散步等一般生活建议，症状应建议咨询专业人士；
- 避免刻板性别角色、容貌羞辱、节食压力和消费攀比。

## 6. 技术实现要求

除非现有仓库已有明确技术栈，使用：

- iOS 17+、Swift 6、SwiftUI；
- MVVM 或清晰的 feature-based 分层；
- `async/await`；
- Apple WeatherKit 获取天气；开发/测试使用 mock provider；
- Core Location 获取位置，反向地理编码只保留展示所需的城市级信息；
- SwiftData 保存偏好、当日结果、历史和收藏；
- UserNotifications 实现本地每日提醒；
- XCTest / Swift Testing 做规则引擎、日期边界、缓存和 fallback 测试；
- 所有文案放入 String Catalog，为未来中文/英文版本预留本地化能力。

建议模块：

```text
App/
Core/
  DesignSystem/
  Models/
  Persistence/
  Networking/
Features/
  Onboarding/
  Today/
  Calendar/
  Profile/
  ShareCard/
Services/
  WeatherProviding.swift
  FortuneGenerating.swift
  AstronomyProviding.swift
Resources/
Tests/
```

为 `WeatherProviding`、`FortuneGenerating`、时钟和随机 seed 提供 protocol 与依赖注入，使测试完全不依赖网络。不要在 View 中直接访问 WeatherKit、定位或数据库。

### 6.1 状态与异常

- 首次无网络：用季节、日期和星座生成结果，并明确显示 `お天気情報を取得できませんでした`；
- 有旧天气缓存：可显示缓存，但标注更新时间；
- 定位拒绝：展示城市选择器，至少包含东京、大阪、名古屋、札幌、福冈、仙台、广岛、那霸；
- 天气 API 超时：3～5 秒后进入 fallback，不无限 loading；
- 跨时区或午夜：以当前选择城市的本地日期为准，重新生成前保存上一日记录；
- 极端天气：优先显示来自系统/天气服务的客观警示，不用占卜淡化风险；
- 权限状态变化：从系统设置返回后立即刷新 UI。

## 7. 隐私、合规与商业边界

- 位置权限只申请 `When In Use`；不申请后台持续定位；
- 精确经纬度仅用于请求天气，不写入分析日志；持久化时仅保存城市标识和天气摘要；
- 生日、收藏、历史默认仅本地保存；
- 设置页提供删除全部本地数据的入口；
- 准备日语隐私政策占位页，并准确列出数据用途与第三方服务；
- App Store 隐私标签必须与实际 SDK 和网络行为一致；
- 首版不要接入广告追踪 SDK；
- 占卜定位为娱乐与自我反思，不承诺真实性；
- 通知不能用恐惧型文案，例如“今天会发生坏事，马上查看”。

建议通知文案池：

- `今日の空から、あなたへ小さなメッセージが届いています。`
- `おはようございます。今日を心地よくするヒントを見てみませんか？`
- `ラッキーカラーを、今日のどこかにひとつ。`

## 8. 可访问性与质量门槛

- 支持 Dynamic Type，最大字号下核心内容不截断；
- VoiceOver 按合理顺序朗读，星级需读为 `5段階中4`；
- 不能只靠颜色表达分数或状态；
- 所有按钮点击区域至少 44×44 pt；
- 浅色/深色模式均检查对比度；
- 天气动画、电量消耗和内存占用保持轻量；
- iPhone SE 尺寸和主流大屏 iPhone 均无布局溢出；
- 对日期、时区、星座边界日以及闰日写测试；
- 使用固定 clock 和 mock 天气做 screenshot/UI 测试，避免快照每天变化。

## 10. 验收场景（Given / When / Then）

1. **首次正常使用**：Given 新用户允许定位，When 完成生日设置，Then 10 秒内看到包含本地天气的完整日语占卜。
2. **拒绝定位**：Given 用户拒绝定位，When 选择东京，Then App 正常生成东京天气版本，且不重复弹权限框。
3. **完全离线**：Given 无缓存且无网络，When 打开 App，Then 能看到不含伪造天气的完整 fallback 占卜。
4. **结果一致**：Given 同一日期、星座、城市和天气快照，When 多次打开或刷新，Then 核心占卜完全一致。
5. **跨日更新**：Given App 跨过当地午夜，When 回到前台，Then 昨日内容进入历史，今日内容更新。
6. **分享隐私**：Given 用户生成分享卡，When 查看导出图片，Then 图片中没有昵称、位置或生日。
7. **权限后置**：Given 用户尚未点击开启提醒，Then App 不请求通知权限；When 用户主动开启，Then 才出现系统授权框。
8. **内容安全**：Given 低运势或恶劣天气，Then 文案仍温和、具体，不恐吓、不做健康或灾害预测。
9. **可访问性**：Given 开启最大 Dynamic Type 和 VoiceOver，Then 核心流程仍可完成且星级读法明确。
10. **数据删除**：Given 用户点击删除并确认，Then 本地生日、历史、收藏、城市偏好全部删除并回到初始状态。

## 12. MVP 之外暂不实现

- 付费订阅、广告、社交 Feed、用户私信；
- 出生盘、合盘或需要出生时间的复杂占星；
- 服务端账号同步；
- AI 聊天陪伴；
- 后台持续定位；
- 以购买商品为核心的“开运”推荐。

完成标准不是“页面看起来像占卜 App”，而是：**一位日本用户可以放心地每天打开，快速获得与当天天气有关、语言自然、视觉精致且真正能采取行动的温柔提示。**
